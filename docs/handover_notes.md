# 📝 奧客戰鬥重構與對稱 UI 實作交接文件

本文件詳細記錄了 2026-05-23 本次對話中完成的**雙向對稱、單一敵人與敵方道具卡系統**的重構細節，便於下一次對話中讓 AI 助手能完美接軌、無縫理解當前的專案架構。

---

## 🔮 專案現狀與本次對話成果

我們成功將遊戲的戰鬥結構從傳統的「1對多實體」模式，重構升級為雙向平衡、完美鏡像的 **Deck vs. Deck（卡牌對決）** 模式。

### 1. 極致對稱的 UI 佈局 (Symmetric UI Layout)
* **左右水平鏡像**：
  * **左側 我方老奶奶 (`PlayerSide`)**：350x650 控制區，包含大頭像、血條、HP數值、縱向排列的食物卡牌手牌（`CardHand`）。
  * **右側 奧客敵方 (`EnemySide`)**：350x650 控制區，包含奧客大頭像、總血量條、HP數值、縱向排列的道具卡手牌（`ItemCardContainer`）。
* **無縫自適應尺寸**：左右兩邊在畫面上構成完美的幾何鏡像，高度、間距與各 UI 元件的位置完美平齊。

### 2. 奧客與道具卡系統 (Enemy & Item Cards Architecture)
* **單一總血量**：戰鬥只會存在一個活躍的敵方實體（目前為「奧客小鬼 Brat」，300 HP），不再像以前一樣有多個怪物血條。
* **道具卡技能載體**：
  * 敵方不再以多個實體戰鬥，而是身上配置 `1~4` 張**獨立 CD 倒數的道具卡**（例如水球、臭彈、尖叫）。
  * 道具卡沒有獨立血量，而是作為奧客的回合計時器與技能觸發媒介。
  * **CD 高亮警告**：當道具卡的當前 CD 剩餘 1 回合時，CD 字體會自動變為**紅色高亮**，警示玩家威脅來臨。

### 3. 被動封鎖（冰凍/鎖定）系統 (Frozen / Locking Mechanics)
* **精準指向**：玩家可以用滑鼠點選右側奧客的特定道具卡（被選中的道具卡會亮起紅色選取外框 `SelectionFrame`）。
* **冰凍阻斷**：
  * 當玩家打出「延緩 CD」技能的食物手牌時（如貓頭鷹 Owl 牌），會直接對**被指向的該張敵方道具卡**施加封鎖（增加 `lock_turns`）。
  * 被封鎖的道具卡會觸發精美的**冰藍色遮罩與 FROZEN 狀態標籤**，且在下一個回合，該卡牌的 **CD 會被成功阻斷（保持原數值不減少）**，同時扣減封鎖回合，直至封鎖解除。

### 4. 槽位指示燈號重見天日 (Slot Indicators Restored)
* **裁切 Bug 解決**：定位出以前因為套用 `854` 像素高度認定的 SubViewport 3D/Shader 投影，而把位於 Y 座標 `864`（槽位 719 + 燈號偏移 145）的指示燈裁切掉的 Bug。
* **上移修正**：將燈號上移 30 像素（`offset_top = 115`，Y 座標回到 `834`），成功讓指示燈在透視畫面上重新正常變色發光！

### 5. 零延遲選取框切換 (Instant Selection Frame)
* **點擊即時響應**：解決了切換食物卡時，選取框要等到下一次彈珠撞擊觸發 `update_ui` 才會改變的視覺延遲。現在點擊食物卡的**瞬間**，選取框會以零延遲的流暢度立刻切換！

## 🛠️ 重要檔案變更與命名對照

為保持專案結構的極致整潔，我們完全遵守了專案的模組化特徵規範，並將所有怪物件命名與變數語意永久替換為 Enemy：

| 檔案路徑 | 類型 | 職責說明 |
| :--- | :---: | :--- |
| `gameplay/cards/item/ItemCardResource.gd` | **[NEW]** | 敵方道具卡的數據資源類（Resource），包含名稱、圖示、CD及 lock_turns。 |
| `gameplay/cards/item/components/ItemCardWidget.gd` | **[NEW]** | 敵方道具卡的控制腳本，處理 CD 高亮警告、鎖定（冰凍）的冰藍色視覺覆蓋。 |
| `gameplay/cards/item/components/ItemCardWidget.tscn` | **[NEW]** | 敵方道具卡場景檔（由 `EnemyWidget.tscn` 改名並移來），移除血量 UI，專注於 CD 及鎖定遮罩。 |
| `gameplay/combat/CombatUI.gd` | **[MODIFY]** | 綁定左右兩側大頭像與血條，同步雙向渲染老奶奶手牌與奧客道具卡，實作零延遲選取框刷新。 |
| `gameplay/combat/CombatUI.tscn` | **[MODIFY]** | 重新建構 `EnemySide` 的 Control 容器，使其在空間幾何上與左側構成完美對稱。 |
| `gameplay/combat/CombatManager.gd` | **[MODIFY]** | 重組戰鬥狀態機，管理單一奧客與多張道具卡 CD 回合扣減、凍結阻斷、以及指向封鎖邏輯。 |
| `core/Main.gd` | **[MODIFY]** | 調整戰鬥數據更新（`combat_updated`）接收簽章，確保資料流與 UI 連接通暢。 |
| `gameplay/table/components/ScoreZone.tscn` | **[MODIFY]** | 將指示燈（Indicator）往上平移 30 像素，避免被 SubViewport 視口邊界裁切。 |

> [!WARNING]
> 為了避免專案出現重覆定義與混淆，舊的 `EnemyWidget.gd` / `.tscn`（位於 `res://gameplay/entities/enemy/`）與舊的 `CardWidget` 相關暫存檔**已徹底被安全刪除**。

## 🔍 完整的手動測試路徑 (Manual Test Cases)

當您在 Godot 中拉取最新代碼並執行 **F5** 啟動遊戲後，可以依序測試以下功能：

1. **對稱佈局與燈號驗證**：
   * 進入戰鬥畫面，確認左側「老奶奶」與右側「奧客小鬼」頭像、血條是否水平對齊。
   * 確認奧客身上的 3 張道具卡（水球、臭彈、尖叫）是否以縱向列表形式精美呈現在右側。
   * 確認彈珠台底部的 8 個槽位指示燈是否恢復亮起（依據當前選取的食物卡類型亮起對應顏色）。
2. **手牌點擊即時響應**：
   * 用滑鼠隨意點擊下方的食物手牌，確認黃色/加亮的選取外框是否在點擊的**瞬間立刻完成切換**，沒有任何延遲。
3. **CD 倒數扣減與紅色高亮**：
   * 發射彈珠，每個回合結束後，觀察右側奧客道具卡的 CD 是否會依序減 1。
   * 當某張道具卡的 CD 剩下 1 時，確認其字體是否轉為紅色高亮警示。
   * 當 CD 歸零時，確認該道具卡發動效果，扣除老奶奶的血量，且該卡牌 CD 恢復為預設值。
4. **冰凍/封鎖阻斷測試**：
   * 用滑鼠點選右側的「臭彈」卡牌，確認其亮起紅色選取框。
   * 選擇左下角帶有封鎖技能的「貓頭鷹 Owl」卡牌，打出並擊中對應槽位。
   * **預期效果**：右側的「臭彈」卡牌會立即被冰凍——卡面疊加半透明藍色遮罩、顯示「FROZEN (N)」。在下一個回合結束時，該張卡牌的 CD **不會減少**（成功被凍結阻斷），且其 lock_turns 減少 1。

## 🚀 建議的下一步開發規劃 (Next Steps)

如果您之後想繼續擴充戰鬥系統，可以從以下幾個方向著手：

1. **支援多關卡奧客輪替 (Multi-stage Enemies)**：
   * 實作一個奧客清單（如 Brat、Gangster、Inspector），在奧客總 HP 被打空並觸發 `enemy_defeated` 時，進入下一關並載入下一個奧客的頭像、名字、以及它專屬配置的 1~4 種道具卡資源。
2. **新增多元化的道具卡功能 (More Diverse Item Cards)**：
   * 除了純傷害類型外，可以新增例如「護盾（降低奧客受到的傷害）」、「干擾（干預玩家發射台）」或「吸血」等多元的 `ItemCardResource`，讓戰鬥的卡牌克制更加多變。
3. **添加被冰凍時的粒子或音效 (VFX & SFX)**：
   * 在 `ItemCardWidget` 被實施封鎖（Lock）的瞬間，加入一個破冰或結冰的微型動畫與音效，進一步提昇精緻的打擊與回饋感。
